🐼 Panda Agent — OSS Desktop V1
1. What are we building?

Panda Agent is an open-source AI Data Analyst Desktop application.

Panda ka kaam sirf CSV clean karna nahi hai. Ye user ke business/data sources ko access karke:

data samjhega
relevant data find karega
data quality check karega
calculations karega
trends/anomalies identify karega
possible causes investigate karega
hypotheses test karega
evidence verify karega
charts/reports banayega
analysis ko save karega
aur user ke question ka evidence-based answer dega.
Core philosophy

One brain, many specialized hands.

Ek hi Panda Agent reasoning karega. Alag-alag agents bana kar coordination nahi karenge.

LLM reason karega.
Tools actual computation/execution karenge.

LLM ko huge raw datasets directly context mein nahi diye jayenge.

2. Panda ka exact example

User Panda ko desktop app mein poochta hai:

“Why did my sales drop in August?”

Panda blindly saare data ko LLM mein nahi daalega.

Step 1 — Understand question

Panda identify karega:

Metric: Revenue / Sales
Period: August
Comparison: Previous comparable period
Question: Root-cause analysis
Step 2 — Find authoritative data

Data Catalog dekhega:

Revenue
├── Shopify → Orders        [Authoritative]
├── Stripe → Payments
└── PostgreSQL → Sales Summary

Panda decide karega ki revenue calculation ke liye Shopify Orders authoritative source hai.

Step 3 — Query only what is needed

For example:

August revenue
→ $72,431

July revenue
→ $100,320

Panda khud calculation karega:

Change = -27.8%

LLM ko 500,000 order rows nahi milenge.

Usko structured result milega:

{
  "metric": "revenue",
  "august": 72431,
  "july": 100320,
  "change_percent": -27.8
}
Step 4 — Investigate drivers

Panda ab candidate drivers investigate karega:

Revenue
├── Orders
├── Average Order Value
├── Products
├── Customers
├── Geography
├── Discounts
└── Other relevant dimensions

Example:

Orders:
July   → 4,210
August → 3,158
Change → -25.0%

AOV:
July   → $23.83
August → $22.94
Change → -3.7%

Panda sees that order volume explains much more of the revenue decline.

Step 5 — Drill down

Panda groups orders by product.

Product C
Units:
July   → 1,240
August → 521

Change → -58%

Then it checks inventory data.

Product C inventory
→ Stockout detected
→ 17 days
Step 6 — Hypothesis

Panda creates:

Hypothesis: Product C stockout materially contributed to the August revenue decline.

Then it tests that hypothesis.

It checks:

timing
magnitude
contribution to overall decline
alternative explanations
availability of supporting data
Step 7 — Evidence

Suppose Panda calculates:

Total revenue decline:
$27,889

Estimated Product C contribution:
$18,900

Contribution:
~68%

Now Panda has evidence.

Step 8 — Final answer

Something like:

August revenue decreased by 27.8% compared with July.

The largest measurable driver was Product C. Its unit sales fell 58% during August, and inventory data shows a 17-day stockout during the same period. Product C accounts for approximately 68% of the total revenue decline.

Based on the available data, the Product C stockout is the strongest supported explanation for the decline.

Limitation: Panda could not evaluate X because that data source wasn't connected.

That's Panda.

Not:

“I think your sales dropped because customers lost interest.”

No bullshit. 😄

3. Adaptive investigation

Workflow rigid waterfall nahi hoga.

It will be a bounded adaptive investigation loop.

Question
   ↓
Understand
   ↓
Find Source
   ↓
Query
   ↓
Validate
   ↓
Analyze
   ↓
Find Driver
   ↓
Investigate
   ↓
Hypothesis
   ↓
Test
   ↓
Verify
   ↓
Enough Evidence?
   ├── No → Fetch/Query More Data
   │          ↓
   │       Continue Investigation
   │
   └── Yes
        ↓
     Finding
        ↓
     Artifact

Example mein Product C stockout mila aur Panda ko inventory data ki zarurat padi, toh investigation wapas data access layer par ja sakti hai.

Lekin endless loop nahi chalega.

Investigation ke paas:

stopping criteria
iteration limits
query limits
timeout
duplicate-query protection
evidence requirements

honge.

19. What Panda V1 is NOT

❌ Multi-agent system
❌ Autonomous business operator
❌ CRM
❌ Local LLM
❌ Local vector DB
❌ CLI-first product
❌ Docker requirement for users
❌ Raw datasets directly into LLM context
❌ Blindly searching every connector
❌ Unrestricted Python execution
❌ Giant prompt as “intelligence”
❌ WhatsApp connector
❌ Complex distributed infrastructure
❌ Hosted SaaS implementation right now

Bas ek line mein Panda V1:

Panda is an open-source desktop AI Data Analyst that connects to real data sources, performs deterministic analysis outside the LLM, investigates questions through an adaptive evidence-driven loop, and gives users verified, explainable findings and artifacts.
